# Link loads against the kinematics benchmark tools

KinematiK's axial force in each suspension member (`suspension/loadpath.py`), compared with the tools the kinematics
was benchmarked against, on the same three corners (front_v11_final, rear_v11_final, front_v11_joints50) at the design
position, under four wheel loads: bump, 1.5 g-class corner with aligning torque, outboard braking, and corner with
shaft-reacted drive at the wheel centre.

Load cases and limits are in `limits.json`, registered on 14 Nov 2026 before any comparison was run. Pass rule: every
member, every case, every corner, |KinematiK − tool| ≤ abs_N + rel·|tool|.

| Tool | Limit | Status | Largest difference |
|---|---|---|---|
| Independent static solve (`scripts/independent_link_loads.py`, SciPy `fsolve`, no shared code) | 0.5 N + 0.1 % | **Pass**, all 3 corners | 0.017 N (rear, brake, UR); 1.1 % of the limit |
| Adams View 2026.1 | 0.5 N + 0.1 % | Not run yet | |
| Lotus Suspension Analysis | 2 N + 0.5 % | Not available (no licence); see below | |
| Applied Racing Dynamics | 2 N + 0.5 % | Not run yet | |

The independent solve uses a different formulation: KinematiK writes six equilibrium equations in six unknown forces
(force method); the check makes every member an axial spring of a different stiffness and solves the upright's pose
with full nonlinear geometry (displacement method). For a determinate corner the forces cannot depend on the
stiffnesses. The 0.017 N left over is the finite stiffness moving the geometry by about 1e-4 mm.

| File | What it is |
|---|---|
| `limits.json` | Load cases, limits, pass rule, registration date |
| `<corner>.cmd` | Adams View command file, generated by `scripts/link_load_benchmark.py --write`. Each member is a link, spherical at the upright and Hooke at the chassis (zero degrees of freedom); the four cases are applied one per step (time 0–3); measures `T_UF` … `T_PR` are the axial force, + tension |
| `<corner>.tab` | (to add) the table Adams View exports after the run, same export as the kinematics benchmark |
| `ard_results.csv` | Template: enter the member forces from each tool, N, + tension. A corner with any blank cell counts as not run |

To run the Adams side: File > Import > Adams View Command File, run, then PostProcessor > File > Export > Table
(spreadsheet) with `T_UF`, `T_UR`, `T_LF`, `T_LR`, `T_TR`, `T_PR`, saved as `<corner>.tab`. The deck has not been
imported into Adams yet; if Adams View rejects a line on first import (the force_vector / torque_vector commands are
new relative to the kinematics deck), fix the generator, not the file.

For ARD: build each corner from `manifests/<corner>.recorded.genesis.json` (winner_hardpoints) with the
pushrod to a fixed point at `rocker_pushrod`, apply the loads in `limits.json` (Fx_wc at the wheel centre, Mz about
vertical), and copy each member force into the CSV. Watch each tool's sign convention: this file is + tension.

What this shows when complete: the same idealisation (rigid, pin-jointed two-force members) gives the same member forces
in independent solvers. What it does not show: the forces on a built car. Bushing compliance, bending in a wishbone
leg and tyre load estimates are outside it; that needs the gauged-link measurement in the validation plan.

Why no Lotus comparison: the Lotus kinematics benchmark uses the published Lotus results of Arevalo et al. (2018).
That paper's member forces (tables 5, 6) are not Lotus output but the authors' hand solve, the patch loads behind them
are not published, and run backwards through the paper's own hardpoints they do not balance the load they describe:
the obstacle case, a vertical force at the wheel centre, comes back with 372 N longitudinal and 300 N lateral (front)
and 2607 N lateral (rear) under the best of eight readings of its conventions. Checked, not usable:
`scripts/arevalo_link_load_check.py`.

Re-run: `python scripts/link_load_benchmark.py` and `pytest tests/test_link_load_benchmark.py`.
